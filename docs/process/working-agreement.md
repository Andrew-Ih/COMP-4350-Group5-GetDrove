## 3. Roles and responsibilities

Everyone is responsible for development. These are additional roles on top of that.

| Role | Responsibility | Assigned to |
|---|---|---|
| Task Leader | Keeps us on track and reminds us when tasks are due | Fola |
| Project Coordinator | Organises meetings, tracks deadlines | Chimdi |
| Technical Lead | Oversees technical decisions and code quality | Rayan |
| Documentation Lead | Maintains the README and docs | Daniel |
| GitHub Manager | Manages repo structure, merges (including releases to `main`), and issues | Andrew |
| Quality Checker | Reviews work before submission | Kelvin |

Roles stay with the assigned person for the whole project unless the team agrees to change them. We revisit roles at the start of each sprint, and if someone's workload or availability changes, we rotate or share the role by group agreement and record the change in our meeting notes.

## 4. Communication

Our primary channel is Discord. Expected response times, escalation, and meeting details are in the [communication protocol](communication.md).

## 5. Meetings

We meet 2–3 times a week on Discord, whenever everyone is free. Meeting norms and what happens when someone can't attend are in the [communication protocol](communication.md#meetings).

## 6. Work expectations

- **Assigning tasks:** through GitHub Issues and our project board. See [planning practices](planning.md).
- **Definition of done:** a task is done when the team approves it by consensus. How that approval happens (review, tests, merge) is set out in the [Definition of Done](planning.md#definition-of-done).
- **Code quality and documentation:** clean code with comments, documentation updated whenever code changes, no AI emoji code, and review before major changes. See [coding standards](coding-standards.md).

## 7. Conflict resolution and unmet expectations

If conflict arises or expectations aren't met, we follow this process in order:

1. A designated harmonizer for the group helps resolve it.
2. We stay respectful with each other and talk about it as a group.
3. If things escalate, we ask Lauren to mediate.

Concerns are raised respectfully, as a group discussion.

## 8. Responsible GenAI use

**Allowed uses:**

- ChatGPT for documentation, planning, and research
- Claude for boilerplate code
- GitHub Copilot for secondary review of your own code

**Not allowed:**

- Submitting AI-generated code you don't understand
- Using AI to review pull requests
- Giving AI tools our secrets or data
- Using AI to make backend or architecture decisions

**Key risks we've identified:** hallucination, over-reliance, and AI output that goes out of scope.

**Transparency and accountability:** each of us is accountable for the work we submit, and we are honest with the rest of the team about what AI produced.

## 9. Accountability

If a team member repeatedly misses deadlines or responsibilities, the team will:

1. Hold a team meeting about it with the person.
2. Escalate to Lauren.
