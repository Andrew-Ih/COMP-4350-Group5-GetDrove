# Communication Protocol

> Part of the [team process docs](../../CONTRIBUTING.md). Back to [README](../../README.md).

## Channels

| Channel | Used for |
|---|---|
| Discord | Day-to-day discussion, questions, blockers, and meetings |
| GitHub issues | Discussion and decisions about a specific feature, story, or task |
| GitHub pull requests | Code feedback and review |
| Shared Google Doc | Meeting agendas, notes, and action items |

If a Discord discussion leads to a decision about the work, record it in the related GitHub issue so it isn't lost.

## Response times

| Situation | Respond within |
|---|---|
| Weekdays | 24 hours |
| Weekends | 5 hours |
| During critical deadlines | 1 hour |

These apply to Discord messages and review requests.

## Escalation

Escalation is required when a delay or project issue keeps recurring. We first raise it with the team at a meeting; if it continues, it follows the [conflict resolution](working-agreement.md#7-conflict-resolution-and-unmet-expectations) and [accountability](working-agreement.md#9-accountability) steps in our working agreement.

## Meetings

- **When:** 2–3 times a week, at times when everyone is free.
- **Where:** Discord.
- **Organised by:** the Project Coordinator (Chimdi).

Meeting norms:

- The agenda is shared in advance.
- Meetings start and end on time.
- Cameras on.
- Everyone contributes.
- Action items are documented in our shared Google Doc.

If someone can't attend, they read the action items afterwards and catch up on what they missed.

## Being blocked or unavailable

If you're blocked or falling behind on an assigned issue, say so in Discord as early as possible. If you'll be unavailable, tell the team in advance so your issues can be covered or reassigned (see [adapting assignments](planning.md#adapting-assignments)).
