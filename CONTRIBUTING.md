# Contributing to GetDrove

Our team's process is documented in `docs/process/`. Please read these before contributing.

| Document | What it covers |
|---|---|
| [Working agreement](docs/process/working-agreement.md) | Roles, availability, decision-making, conflict resolution |
| [Communication protocol](docs/process/communication.md) | Channels, response times, meetings |
| [Planning practices](docs/process/planning.md) | Iterations, distributing work, dependencies, adapting assignments, Definition of Done |
| [Git workflow](docs/process/git-workflow.md) | Git Flow branching, naming, releases, hotfixes, commit messages |
| [Coding standards](docs/process/coding-standards.md) | Formatting, naming, code quality, service rules, testing |
| [Code review practices](docs/process/code-review.md) | Pull request rules, approvals, review expectations |

Quick start: pick an issue from the [project board](https://github.com/users/Andrew-Ih/projects/3), assign yourself, create a branch from `develop` following the [naming rules](docs/process/git-workflow.md#branch-names), and open a pull request into `develop` when it's ready.
